ACT tracking policy v2 — software change, 2026-10-15

Purpose
-------
Do not use the peak error of one successful ROS H2 execution as an ACT
dynamic fault limit. This change separates performance observations from
checks which stop execution. It does not calibrate or certify new fault limits.

Behavior
--------
For the task profile AFTER explicit START:
* Right J1-J7 tracking error is recorded, without an error-magnitude stop.
* Uniform 0.03 rad diagnostic references only flag performance warnings.
  They are display references, not robot limits or task-success criteria.
* The right gripper retains the existing 0.03 rad experimental tracking stop.
  This is NOT validated force/contact protection. No contact override is added.
* Raw ACT prediction, model/preprocessing, executor blending/filtering, command
  velocity/acceleration limits, duration, and hardware gains are unchanged.

Unchanged blocking checks include HOME/initial reference and pre-START holding
admission; short commissioning profile tracking; ROS/URDF position bounds;
measured speed, feedback/action freshness, watchdog, finite values; geometric
collision sweeps; controller/CAN health, ownership and competing-command checks.
These retain their previous evidence and limitations; they are not all certified
hardware safety limits. In particular static scene checks do not model arbitrary
obstacles, contact forces, braking distance or physical tracking dynamics.

The return-HOME stationary snapshot uses stationary_recovery_contract(), whose
existing per-joint allowances and sealed evidence checks are unchanged. It is
no longer the source of ACT running stop limits. Return-HOME still requires
stationary fresh feedback and a separately validated path.

Known limitation: there is no newly validated dynamic J1-J7 tracking-fault or
stall limit. Monitoring-only error does not detect a stall as a tracking fault.
The observed persistent J6 offset has not been repaired by this policy change.

Audit fields
------------
bridge.jsonl guard decisions now record:
  tracking_reference_rad / tracking_reference_kind
  tracking_error_rad
  tracking_warning_thresholds_rad / tracking_warning_joints
  performance_warnings
  tracking_stop_limits_rad / tracking_stop_joints
  errors / interventions
Null arm stop limits mean monitoring-only, not a zero-radian limit. The error
compares the latest feedback to the preceding guard command; it is explicitly
NOT described as a time-aligned ROS controller error. ROS and CAN records remain
available to investigate actual command timing, output and motor response.

Migration
---------
execution_profile.tracking_policy_version is now 2. Old configs are rejected
before a new bridge connects to the authority. Do not edit old configs or erase
old trial evidence. No live process, active configuration, gateway fault or
motor state was changed during this software work.

The existing manual recovery prerequisites still apply: ROS/gateway keep
holding; stop old policy/Dora; inspect the latched fault and drained holding
state; manually recover HOME when necessary before a new trial. Only after
that verified state, use:
  source /home/lushilin/openarm_vla_ws/results/act_manual_orhyr6wr/environment.sh
  actctl next-trial --profile task
This archives the old motion attempt and generates the v2 configuration. It
does not reset a fault, move to HOME or start ACT. It must refuse a faulted
gateway. Do not repeat H1/H2 solely to apply this software change.

without sourcing that environment had 4 missing-import failures and 5 skips;
